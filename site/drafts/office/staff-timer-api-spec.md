# 作業タイマー → 3Dオフィス連携API 仕様（依頼書）

> 依頼元：はなさか 3Dオフィスダッシュボード（VPS `site/office/`）
> 目的：社員が「いま作業中かどうか」「何の作業をしているか」を3Dオフィスに表示する。
> 作成日：2026-07-21
>
> ⚠️ **これは初期依頼時の仕様（歴史記録）**。実装は依頼後に変更済み＝実際のエンドポイントは
> `/api/external/office-status`・認証は `X-API-TOKEN` ヘッダ・VPS側キャッシュは5分
> （現行仕様の正は `site/tools/office/status.php` のコード・コメント。2026-07-28 注記）

## 1. 作ってほしいもの（1本だけ）

**GET の読み取り専用エンドポイント**。全社員の現在状態を JSON で返す。

- 例：`GET /api/office-status`（パスは任意。決まったものを教えてください）
- メソッドは GET のみ。**書き込み系は一切不要**（タイマーの操作はしない）
- `Content-Type: application/json; charset=UTF-8`

## 2. レスポンス形式（この形でお願いします）

```json
{
  "generated_at": "2026-07-21T10:12:34+09:00",
  "employees": [
    {
      "id": "emp-001",
      "name": "山田",
      "working": true,
      "task": {
        "title": "コーディング",
        "client": "○○社",
        "project": "コーポレートサイト改修",
        "started_at": "2026-07-21T09:30:00+09:00"
      }
    },
    {
      "id": "emp-002",
      "name": "佐藤",
      "working": false,
      "task": null
    }
  ]
}
```

### フィールド要件

| フィールド | 必須 | 内容 |
|---|---|---|
| `generated_at` | ✅ | サーバがこのレスポンスを作った時刻。ISO8601・タイムゾーン付き（`+09:00`） |
| `employees[]` | ✅ | **在籍社員全員**を毎回返す（タイマー停止中の人も `working: false` で含める）。表示側で「誰がいて誰が席を外しているか」を描くため |
| `id` | ✅ | 社員の**安定ID**（表示名を変えても変わらないもの。DBのPK等） |
| `name` | ✅ | 表示名（画面にそのまま出します） |
| `working` | ✅ | タイマーが現在起動中なら `true` |
| `task` | ✅ | `working: false` のときは `null`。中身は下記 |
| `task.title` | ✅ | いまの作業名（タイマーに登録されている作業内容） |
| `task.client` / `task.project` | 任意 | 分かれば。無ければ省略か `null` で可 |
| `task.started_at` | ✅ | 今回のタイマー開始時刻（ISO8601・TZ付き）。経過時間の表示に使う |

### あると嬉しい（任意・後回しで可）

- `status`: `"working" / "paused" / "off"` の3値（休憩中を区別できるなら）
- `today_minutes`: 本日の合計作業分数（社員ごと）

## 3. 認証・到達性

- 呼び出し元は **VPS のサーバサイド（PHP）だけ**。ブラウザから直接は叩かない（トークンは画面に出ない）
- 認証はどちらかで：
  1. **Bearer トークン**：`Authorization: Bearer <token>`（推奨）。トークンは両側とも `.env` 管理
  2. Tailscale 内限定＋IP制限（同一 tailnet にあるなら）
- VPS（Tailscale IP `100.123.104.87`）から到達できる URL を教えてください

## 4. 性能・運用の前提

- 呼び出し頻度：**30秒に1回程度**（VPS側でキャッシュするので、それ以上は叩きません）
- 応答は軽く（目安 1秒以内・全件で数KB）
- 障害時は non-200 を返してくれれば OK（VPS側は「取得失敗」表示にフォールバック）
- **後方互換**：フィールドの追加は自由／既存フィールドの改名・削除はしない

## 5. 決めて返してほしいこと（3点だけ）

1. エンドポイントの **URL**
2. 認証方式（Bearer トークン or IP制限）と、トークンの受け渡し方法
3. `id` として何を使うか（社員番号？DBのID？）

---

受け取り後のVPS側の実装（こちらの作業）：`site/tools/office/status.php` がサーバサイドでこのAPIを取得（トークンは `.env`・30秒キャッシュ）→ 3Dオフィスに社員キャラを追加し、作業中の社員には頭上に「🔨 作業名（経過時間）」を表示する予定です。
