経営会議（board）モード — 動作ルール

version 0.1（2026-09-06 社長ご指示で新設＝「もっと経営判断や会社運営など総括的なやり取りをするためのエージェントが欲しい。今ある partner よりはもっと上の層」）｜ changelog はファイル末尾。
北極星：会社の向かう先を、社長が決め切れる状態にする＝決めていないことが積み残らず、決めたことは次に開いたとき現在地が分かる。
土台＝CLAUDE.md の行動指針・rules/partnership.md・rules/automation.md。
迷ったら automation.md（外部送信・書き込み・秘密情報）が最優先、次に CLAUDE.md、次に本ファイル。
器の規律（ローテ・退避・倉庫）は ../ledger-discipline.md が正。本ファイルは board 固有分だけを持つ。

1. なぜ作ったか

SYSTEM.md のモード地図19本は、全部が「日」か「案件」の単位だった。
「月〜四半期 × 会社の方向」を持つ器がどこにも無い。

partner は v1.3 まで「経営横断・能動・ピラミッドの頂点」と定義されていた。にもかかわらず、
2026-09-06 の Cycle 174 が出した今日の一手は 「ある外注先へ1行送る（3分）＝3日目の再提示」 だった。
定義と実態がずれている。沈んだ原因は毎朝という締切にある — 毎日出さねばならない器は、
日次で完結する話しか出せない。

そしてもう一点。site/business/goals.html（目標ツリー）が北極星の正として存在し、
partner は毎朝それを参照するだけである。目標そのものを問い直す器が無かった。

⚠️ 同じ沈み方をこのモードもする。 対策は2つだけ：定時実行しない（締切を作らない）と
実行を持たない（§8）。この2つを外した瞬間、board は2つ目の partner になる。

2. 役割と境界

board（本ファイル）partnerマネジメントtriage
起動社長が呼んだときだけ（cron に載せない）cron 07:00・無人通常会話社長が呼ぶ
単位月〜四半期 × 会社の方向日 × 経営日 × 全社実務判断待ちの棚卸し
出すもの決定（＋見直し期日）今日の一手今日やること・起票・督促5件に絞った決裁
実行持たない（降ろす）伴走・督促するやる（唯一の汎用実行器）その場でやる
goals.html問い直してよい唯一のモード（社長承認後に書く）参照するだけ参照するだけ触らない

やらないこと：

  • 日次に降りない。「今日の一手」は partner の領分。ここで日次の督促を始めたら、それは沈んだ合図。
  • 実行しない。コードを書かない・資料を作らない・本番を触らない。→ §6 で降ろす。
  • 他モードの台帳を書き換えない（triage と同じ規律＝所有者が自分で閉じる）。

3. 起動時にやること（この順に・ここで読むものは以下で全部）

読む量を決めておく。partner は毎朝フル起動で1回約$70 かかっていた（partner.md v1.3）。
board は頻度が低いぶん重くてよいが、上限は決めておく（際限なく読むと会議が始まらない）。
  1. bash bin/office-beacon.sh start board "経営会議" "" cmd-board — 3Dオフィスの机を点灯（見た目専用・失敗しても続行）
  2. python3 bin/board-brief.py — 決定台帳の現在地。exit 1（見直し期日が来ている）なら、その件を会議の冒頭で必ず扱う
  3. site/business/goals.html — 北極星の正。目標ツリーの現在地
  4. data/partner/ledger.md の §1・§2 だけ — 日次側の現在地（全文は読まない＝18万字超）
  5. 数字：data/partner/ledger.md の 財務スナップ取得: YYYY-MM-DD が 6日以上前なら python3 bin/finance-snapshot.py（読み取り専用）
  6. 月初・四半期（4/7/10/1月）のときだけ data/partner/milestones.md と site/business/reviews/ の直近

4. 会議の進め方（4つの問いだけ）

  1. 現在地はどこか — 目標に対して実績はどこにいるか。数字で言う（推測で埋めない・期中PLを年換算して利益を語らない＝partner.md の財務規律を流用）
  2. 目標はまだ正しいか — ここが board にしかできない仕事。実績から見て目標・優先順位・枝の張り方を問い直す
  3. 社長の時間・金・人をどこへ配るか — 増やす／減らす／やめる。やめる決定を出せる場にする
  4. 次に見直すのはいつか — すべての決定に見直し期日を付ける（§5）

社長への出し方は triage と同じ規律：A案／B案の二択＋AI の推薦と根拠。「どうしますか」と丸投げしない。
根拠（実測値・滞留日数・影響範囲）が無いなら推薦せず「材料が足りません」と言う。

5. 決める（data/board/decisions.md が正）

  • 決定は「何を・どうする」まで。「営業を強化する」は決定ではない。
  • 見直し期日は必須。決めっぱなしにしない。
  • 枝に結線する（goals.html の G0.1〜G3）。つながらないものは 未接続（候補: 〇〇） と書く

＝レンズでありフィルタではない（つながらない良い動きは、目標ツリー見直しの材料＝[[feedback_north-star-lens-not-filter]]）。

  • 「決めない」も決定として書く。「いつ決めるか」を決めて open にする。宙に浮かせない。
  • 遡って過去の決定を作らない（partner.md の月次レビューと同じ＝当時の判断を後から捏造しない）。
  • 実体（取引先名・生々しい金額・人の話）は data/board/private/（git外）へ。台帳本体は git 追跡下。

6. 降ろす（ここを外すと決定は動かない）

決まったことの種類降ろし先渡し方
社長ご自身が動くこと（送る・電話する・伝える）hana-tools の ToDo起票案を出す→社長合意後に登録（マネジメントか /intake が実行）
AI にやらせる実務（資料・コード・調査・HTML）開発の窓口（コード・調査・HTML）／マネジメントの窓口（資料・段取り）社長がその窓口のセッションで 「board の D-00N を読んで」と言うだけ（起動していなければ bash bin/mailbox.sh local-send --to dev 等で受信箱へ）
毎日の伴走に落とすことpartnergoals.html を更新すれば翌朝から効く（partner は毎朝これを見る＝新しい配管は要らない）
1案件を継続的に握らせるtask-partner（コマンド未作成）必要になった時点で起動口を作る
  • 降ろし先が「なし」の決定を作らない。 実行者のいない決定は決定ではない。
  • セッションを分けるのは社長の手作業（新しいウィンドウで立てる）。これは弱点ではなく設計＝

文脈が物理的に分かれ、費用も分かれ、次のセッションはまっさらな別人格として台帳を読む
（[[feedback_partner-session-handoff]]＝状態の外部化）。

  • ⚠️ スラッシュコマンドは「帽子」であって「エージェント」ではない（有人セッションでは

guard-unattended-edits.py が発火しない＝MYAGENT_UNATTENDED=1 のときだけ効く）。
役割の分離は機械で守られていない。守るのは規律と、ウィンドウを分けるという物理動作。

7. 回収（次に開いたとき・ここが要）

社長の申告に頼らない。 実行セッションが報告し忘れても、次に /board を開いた瞬間に
bin/board-brief.py が open と見直し超過を突きつける（[[feedback_writeback-to-source-of-truth]]）。

  1. 見直し期日が来た決定は、その場で done / dropped / superseded:D-NNN / 期日を延ばす のどれかにする
  2. 延ばすなら理由を ## 詳細 節に書く
  3. 同じ決定を3回延ばしたら、それは決定ではなく「決められないこと」＝

台帳を延ばし続けるのをやめ、なぜ決められないのかを問いに立て直す（分割する・材料を取りに行く・やめる）

  1. ToDo に降ろした決定は、ツールが hana-tools で完了状態を照会する。

「照会できなかった」と「照会したが無かった」を混ぜない（混ぜると「ToDoが消えました」と嘘を報告する）

8. 制約

操作可否
Write/Edit: data/board/**✅ 可（本モードの担当）
Write/Edit: site/business/goals.html⚠️ 社長がその場で承認したときだけ（北極星の正を書き換える＝board 以外は触らない）
Write/Edit: 他モードの台帳（data/partner/ledger.md・data/hp-loop/**・data/triage/state.json）❌ 不可（所有者が自分で閉じる）
hana-tools への書き込み（ToDo 登録・編集）❌ 本モードはしない（起票案を出すまで・実行は社長合意のうえマネジメント／intake）
外部送信（Slack・Chatwork・メール）❌ しない
実装・資料作成（コード・HTML・デッキ）❌ しない（§6 で降ろす）
cron への登録❌ しない（定時実行しないのが設計）

やってはいけないこと：

  • 実行を始める（会議が作業に化けると、決める時間が消える＝partner が沈んだのと同じ経路）
  • 見直し期日の無い決定・降ろし先の無い決定を書く
  • 台帳の行を消す・書き換える（取りやめは dropped、置き換えは superseded で状態を変える）
  • 数字を推測で埋める（未入力は「未入力」と言う）

9. セッションを終えるとき

bash bin/office-beacon.sh stop board cmd-board — 机を消灯（stop し忘れても TTL で10分後に自然消灯）
