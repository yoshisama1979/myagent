🔑 サーバ／証明書
（Cycle 033・2026-08-29 実測＋社長回答）		ホスティング＝Xserver VPS（2026-08-28 社長回答＝Q-R13）。Xserver VPS は root を渡す素の VPS＝コントロールパネルに証明書の発行機能は無い（Xserver レンタルサーバの「無料独自SSL」とは別製品）。
証明書（実測 2026-08-29・bin/check-ssl.sh）＝check-rally.com・www.check-rally.com の有効期限がどちらも 2026-11-13 で完全一致＝www 専用の証明書は存在せず、apex 用の1枚を全ホスト名へ出している。curl のエラーは SSL: no alternative certificate subject name matches target hostname＝SAN に www が入っていないだけ。
有効期間＝2026-08-15〜2026-11-13 のちょうど90日 ⇒ Let's Encrypt（ACME 自動更新）＝サーバ内に certbot 等が入っている（推測・確度高）。商用証明書は1年〜13か月なので90日固定はほぼ一意に特定できる。
⇒ 確定事項①：証明書まわりは「VPSパネル」ではなく「サーバ内の設定」（社長のご指示にあった切り分けは、実測で決着＝質問不要になった）。
⇒ 確定事項②：R-R18 は「301 リダイレクトだけ」では直らない＝https://www. は TLS ハンドシェイクが先に失敗するため、ブラウザは HTTP 応答を受け取る前に警告画面で止まり 301 は永遠に届かない。正しい順序＝①証明書の SAN に www を追加（必須）→②www→apex の301。（Cycle 028〜032 の「(推奨) 301 リダイレクト」という記述は Cycle 033 で訂正。）
⇒ 推測①：2026-08-15 の約20分のダウンタイムは、この証明書の自動更新が引き金＝発行日（08-15）と障害日が一致し、certbot renew を standalone 認証で回すと 80番を掴むため Web サーバを一旦止める＝80/443 が同時に即時拒否という当時の観測と症状が一致する。次回更新は 2026-10-14 前後の見込み（Let's Encrypt は残30日で更新）＝再発しうる日。恒久対策＝更新方式を --webroot か --nginx に変える（Web サーバを止めず再読込のみ）→ R-R19。
