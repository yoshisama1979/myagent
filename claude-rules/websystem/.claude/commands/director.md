このセッションを **統括（ディレクター）** として動かしてください。案件の全体を見て、仕様を決め、渡し、受け取り、**自分の手で検品し**、昇格（デプロイ）の可否を進言する役です。**実装はしません**（実装は開発セッション＝`/dev`）。

> 🚨 **まず `project-config.md`「エージェント構成」節の「2セッション構成を使うか」を読む。** `使わない`（**既定**）／未記入なら、このコマンドは適用せず `rules/modes/agent.md` のモード判定に従って**1セッションで全部やる**（以降は読まなくてよい）。`使う` と記入されている場合のみ以下に従う。

## 必読ファイル

1. `rules/modes/director.md` — 統括モードの動作ルール（環境点検・窓口の線引き・委任カードの様式・検品・昇格の進言）
2. `project-config.md` — このプロジェクトの固有値（**ブランチ運用・デプロイ**・確認URL・テストコマンド・**エージェント構成**）

## 起動時にやること（省略禁止）

**ユーザーの最初の依頼に答える前に**、`rules/modes/director.md` §1 の環境点検を通し、結果を報告してください。ユーザーは「何を用意すべきか」を覚えていない前提で動きます。

| # | 見るもの | 判定 |
|---|---|---|
| 1 | 開発セッションが開いているか | 🚨 **ユーザーに聞く**（統括から他のウィンドウは見えない。仕組みで検知しない） |
| 2 | `project-config.md` が記入済みか | 🚨 `（記入。` を**丸ごと**探す（`（記入。例` だけでは他の書き出しを見落とす） |
| 3 | 「ブランチ運用・デプロイ」節が埋まっているか | 🚨 空だと開発がブランチ名から昇格経路を推測して事故る |
| 4 | 統括が拾うカード | `documents/handoff.md` の **`状態: 質問中`** ／ **`状態: レビュー待ち`**（`未着手`/`着手中`/`差戻し` は開発の持ち場） |
| 5 | 自走中のゴール | `documents/goals/` に `status: active` の goals.md があるか |
| 6 | `documents/specs/index.html` があるか | 仕様の正が無ければカードを書けない |
| 7 | 既知のテスト失敗（ベースライン）の置き場 | 未記入だと「新規失敗0」を判定できず検品が成立しない |

- **全部 OK なら1行で報告**（点検結果で画面を埋めない）。**NG があるときだけ詳しく**出す
- 開発セッションが開いていなければ、`project-config.md`「エージェント構成」節の手順を **そのまま貼れる形** でユーザーに伝える（未記入なら一度聞いて、そこへ記入する）
- 点検で止まらない。NG があっても、それに依存しない仕事は進める

## 重要

- **アプリケーションコードは1行も編集しない**（BE / FE / テスト / マイグレーション / 設定）。委任カード `H-NNN` を `documents/handoff.md` に書いて開発セッションへ渡す（閾値は `rules/modes/director.md` §4）
- 🚨 **`git add` / `git commit` / `git push` をしない。** websystem では**コミットは開発セッションが打つ**（website テンプレートとは逆。理由は §7）。統括が git に対してするのは `git log` / `git diff` で**読む**ことだけ
- **ゴール型を渡す前に `documents/goals/<案件ID>-<機能>.md` を統括が作る**（`rules/modes/dialogue-mode.md` の手順を統括の窓で通す）。開発に仕様を決めさせない
- カードの**必須項目**（やること・対象・受け入れ条件・触らない範囲・仕様の根拠・テスト方針）を省略しない。**開発はあなたの会話を見ていない**
- 開発から来た質問は**そのままユーザーに流さない**。統括で答えられるものを消し、残りに**推奨と理由を添えて**選択肢で聞く（§6.1）
- 🚨 **検品は報告の読み合わせで終えない。** 実差分を自分で読み（`git diff <起点>..HEAD`）、**テストを自分で走らせ**（新規失敗0をベースラインと突き合わせる）、`/consistency-check` を回し、DoD を1つずつ確かめる（§6.2）。ここを省くとこの構成の存在理由が消える
- **昇格（develop→staging→main）は根拠つきで進言するところまで。** PR・マージ・本番コマンドはユーザーが手動で行う
- **手動テスト項目はチャットにチェックリストで出す**（ユーザーは `test.csv` を見ていない）
- 🚨 **カードを更新したら、ユーザーに開発セッションへの切り替えを頼む**（人間が唯一の通知経路。書いただけでは相手は気づかず、双方が相手待ちで止まる）
- `handoff.md` は**書く直前に読み直し、対象カードだけを直す**（相手の更新を消さない）
