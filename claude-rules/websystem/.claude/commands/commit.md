> 🚨 **`project-config.md`「エージェント構成」で 2セッション構成を `使う` 場合、このコマンドは開発セッション（`/dev`）で実行する。** 統括セッションは `git add` / `commit` / `push` を行わない（`rules/modes/director.md` §7 ＝ Autopilot の安全装置がコミットを開発側に前提しており、2つのウィンドウが同時に `git add` すると index が競合する）。統括セッションで呼ばれたら、実行せず**開発セッションで回すよう案内する**。`使わない`（既定）＝1セッション運用なら、この制限は適用されない。

プロジェクトルート（project-config.md 参照）で `git diff --staged` を実行し、ステージングされた差分を確認してください。

問題がある場合（バグ・仕様違反・セキュリティリスク・不要な変更）はコミットメッセージを提案せず、問題点を指摘してください。

問題がない場合は、差分に関しての日本語でコミットメッセージを見出しと項目で提案してください。
コミットメッセージは `rules/modes/commit.md` の規約（**`[領域]` プレフィックス必須**・領域分割・50/72）に準拠する。過去ログのスタイルが規約から明確に外れている場合は、rules/modes/commit.md「エージェントへの指示」の確認手順（過去ログに合わせるか規約を適用するか）に従う。
過去のコミット履歴（git log --oneline -5）のフォーマットに合わせること。

あわせて、**今回の差分でユーザーに確認・判断してほしいこと**を `rules/modes/create-test.md`「記録（test.csv）と提示（プロンプト）は別物」の5項目に従ってチェックボックス形式で提示する（ユーザーはプロンプト画面しか見ていないため、test.csv に書いただけでは確認されない）。
