hana-tools のプロジェクトメモへ、残存課題・重要な仕様を登録・更新してください。

## 必読ファイル

1. `rules/modes/hana-memo.md` — API 仕様・全置換の鉄則・HTML の書き方ルール（自己完結の詳細ルール）

## 実行手順

1. 必読ファイルを読み込み、ルールを把握する
2. `project-config.md`「hana-tools プロジェクトメモ連携」欄でベースURL・project_id・visibility を確認する（未記入なら `rules/modes/hana-memo.md` §5 で一覧を取り、**候補を提示してユーザー確認で確定**してから同欄に記入する。AI が単独で ID を決めない）
3. 登録したい内容を確定する（正本＝ `documents/pending-issues.md` 等の開発プロジェクト側ファイル。ファイル側が未更新なら先にそちらを直す）。**読み手はスタッフ＝非開発者**なので、正本を丸写しせず平易な言葉に書き直す（`rules/modes/hana-memo.md` §0.5）
4. **GET で現在のメモ本文を取得**し、既存内容と統合した完全な HTML を作る（`rules/modes/hana-memo.md` §2〜§4 の許可タグ・書き方に従う）。**人手で書かれた既存メモには手を入れず**、自分の追記を別見出しとして足す
5. 統合後の変更点（何を追加・修正するか）と `edit_summary` をユーザーに提示し、**承認を得てから POST** する（`expected_version` で楽観ロック推奨・`409` なら GET からやり直し）
6. レスポンスの `data.body` を確認し、重要な要素がサニタイズで除去されていないかチェックして報告する

## 重要

- **POST は追記ではなく全置換**。GET → 統合 → POST を厳守（他の人が書いた内容を消さない）
- **宛先 project_id を推測で決めない**。誤った ID への POST は別プロジェクトのメモを全置換で消す（サーバはエラーを返さない）
- **API トークンの実値を読まない・表示しない・リポジトリに書かない**（環境変数 `HANASAKA_API_TOKEN` 等を参照するだけ）
- 記録の正本は開発プロジェクト側のファイル（開発者向けの詳細）。共有メモはそれを**スタッフ向けに噛み砕いた要約**（内部の提案番号・技術用語を持ち込まない）
