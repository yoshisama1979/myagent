# 委任台帳（handoff）

**統括セッション（`/director`）と開発セッション（`/dev`）の受け渡しは、このファイルだけが正。**
2つのセッションは別のウィンドウで動き、**互いの会話は見えない**。ここに書かれていないことは、相手にとって存在しない。

> このファイルのパスは **固定**（`documents/handoff.md`）。`project-config.md` で変更できるようにはしていない
> ＝両セッションが別のファイルを見る事故を防ぐため。
>
> 🚨 **`project-config.md`「エージェント構成」で 2セッション構成を `使わない`（既定）** のプロジェクトでは、このファイルは使わない（空のまま置いておく）。

---

## 状態と所有者（この6つだけを使う）

| 状態 | 誰が設定するか | 意味 |
|---|---|---|
| `未着手` | **統括** | 起票した／次ラウンドの指示を書いた。開発が着手できる |
| `着手中` | **開発** | 実装している |
| `質問中` | **開発** | 判断が要る。**統括の回答待ち** |
| `レビュー待ち` | **開発** | 実装とテストが終わった（**未コミット**）。**統括の検品待ち**＝検品を通ったら統括がコミットする |
| `差戻し` | **統括** | 検品で条件未達。開発が直す |
| `クローズ` | **統括** | 検品を通り、DoD を満たし、**統括がコミットまで済ませた**（`rules/modes/director.md` §7） |

- **統括が拾うもの** ＝ `質問中` `レビュー待ち`
- **開発が拾うもの** ＝ `未着手` `着手中` `差戻し`
- 🚨 **各状態を設定できるのは、上の表で決まった側だけ。** 相手が設定した状態を、別の状態へ勝手に書き換えない（例：開発が `質問中` にしたカードを、統括が `着手中` に変えない）
- **ただし持ち場が移る遷移は、受け取った側が次の状態を設定する**（`質問中` → 統括が回答して `未着手` へ／`レビュー待ち` → 統括が `クローズ` か `差戻し` へ／`差戻し` → 開発が `着手中` へ）。ここを「設定した側しか動かせない」と読むと、`質問中` のカードを誰も動かせなくなる

```
統括: 未着手 ──→ 開発: 着手中 ──→ 開発: レビュー待ち ──→ 統括: クローズ
                    │                      │
                    ├──→ 開発: 質問中       ├──→ 統括: 差戻し ──→ 開発: 着手中
                    │        └──→ 統括が回答して 未着手 へ戻す
                    │                      └──→ 統括: 未着手（条件は満たしたが
                    │                             ゴールはまだ途中＝次ラウンドへ）
```

> **`差戻し` と `未着手` の使い分け**（統括が検品したあと）
> - **`差戻し`** ＝ 不合格。受け入れ条件を満たしていないので**やり直す**
> - **`未着手`** ＝ 合格だが**ゴールはまだ途中**。次ラウンドで何をするかを追記して返す
>
> システム開発は1ゴールが複数ラウンドに分かれるため、この2つを混ぜない。混ぜると開発が「直すのか進むのか」を判断できない。

## 書き込むときの約束（両セッション共通）

1. **書く直前にこのファイルを読み直す**（相手が更新しているかもしれない）
2. **対象のカードだけを直す。** ファイル全体を書き戻さない
3. 読んだ状態が**想定と違っていたら、書かずに止まる**（相手が動いた＝前提が変わった）
4. `更新` 行を必ず自分の名前と日時にする

## カードのフォーマット

委任には **ゴール型**（まとまった機能。複数ラウンド回る）と **小口型**（不具合修正・1関数の変更・文言修正）がある。
ゴール型は **統括が先に `documents/goals/<案件ID>-<機能>.md` を作り**、カードはそこへのポインタにする。

```markdown
### H-NNN <やることの見出し>

- 状態: 未着手
- 種別: ゴール型
- 担当: dev-A
- 優先度: 1
- 依存: なし
- 更新: YYYY-MM-DD HH:mm / director

**やること**（1行）

**対象**（必須）
- ゴール記録: `documents/goals/<案件ID>-<機能>.md`（確定仕様と DoD はこちらが正）
  ※小口型なら、触るファイル・領域を直接書く
- 領域: BE / FE / 両方

**受け入れ条件**（必須・機械で判定できる形で）
- [ ] goals.md の DoD をすべて満たす（小口型なら条件を直接書く）
- [ ] BE / FE の自動テストが通り、**新規失敗が0件**（ベースラインは `project-config.md`）
- [ ] 本番ビルド相当の静的チェック（lint / tsc）が通る

**触らない範囲**（必須）
- スコープ外・壊してはいけないもの（**後方互換を壊してはいけない契約**を明記する）

**仕様の根拠**（必須）
- `documents/specs/<該当ページ>.html` の該当箇所。**ここに無い挙動は実装せず質問で返す**

**テスト方針**（必須）
- 自動：何を自動テストでカバーするか
- 手動：何を `documents/test.csv` に残すか

**読むルール**
- 例: `rules/modes/tdd.md` ／ `.claude/rules/api-design.md`

**確認環境**
- `project-config.md`「URL・確認環境」
```

- **`- 状態:` `- 種別:` `- 担当:` `- 優先度:` `- 依存:` `- 更新:` の6行は固定形式**（行頭から書く）。見出しに状態を埋め込まない＝**grep で拾えるようにするため**
- `担当` は**統括が割り当てる**開発セッションの名前（`dev-A` 等）。1 対 1 運用なら常に `dev-A`。未割当は `-`（開発は拾わない）
- **`担当:` 行が無いカード**（この規則より前に起票されたもの）は **`dev-A` 担当とみなす**＝1 対 1 運用の既存プロジェクトはそのまま動く
- `優先度` は 1 が最優先。`依存` は先に終わっている必要があるカード（`H-002` 等・無ければ `なし`）
- 開発は **自分が `担当` のカードのうち、`依存` が解決済みで最も優先度の高いもの**から着手する（ユーザーに順番を聞かない）
- **1カード＝1論点。** 複数の機能をまとめて1カードにしない（検品も差し戻しもできなくなる）
- 通し番号 `H-NNN` は連番で続ける
- 任意行 `- 報告: 軽量`（統括だけが書く）＝1 ファイル・数行・判断を伴わない修正で、開発の報告を軽量様式にする（`rules/modes/developer.md` §7）

報告のフォーマットは `rules/modes/developer.md` §7 を参照（10項目。とくに **コミット材料**・**変更ファイル**・**テスト結果**・**確認できていないこと** を空にしない）。

## 開発セッションが 2 枚以上あるとき（1 対 n）

統括 1 枚に対して開発を複数枚（`dev-A` `dev-B` …）開いてよい。**上限は 3 枚**（人間の中継が枚数分増える・統括の検品が詰まる・対象ファイルの組み合わせが枚数の 2 乗で増える）。

- **カードは統括が `担当:` で割り当てる。開発は自分の担当のカードだけを拾う**（1 対 1 のときの「優先度が最も高いカードを自分で選ぶ」は、2 枚以上では使わない＝同じカードを 2 人が取る事故を構造で消す）
- 開発の名前は `/dev <名前>` の引数。**省略時は `dev-A`** ＝ 1 対 1 運用と互換
- **並行に出す前の交通整理は統括の仕事**（`rules/modes/director.md` の「交通整理」節）：対象ファイルが重なるカードは同時に出さない・共有基盤（DB スキーマ・API 契約・共通コンポーネント）に触るカードは単独で出す
- 相手の担当カードは読んでよいが**書き換えない**（状態の所有者と同じ理屈）
- **開発はカード外の新しい作業を自分で起票しない。** 下の「統括への依頼」節に 1 行書き、統括がカード化する（番号の衝突と交通整理の迂回を防ぐ）
- 🚨 **ゴール型は同時に 1 枚まで。** 並行できるのは小口型だけ（理由は `rules/modes/director.md` §5.3）

## 退避（ローテーション）

次のどちらかに達したら、`クローズ` のカードを古い順に `documents/handoff-archive.md` へ移す（削除しない）。**このファイルはテンプレートに同梱していないので、初回は作成してから移す。**

- **`クローズ` が 50 件を超えた**
- **このファイルが 1000 行を超えた**

`質問中` `レビュー待ち` `差戻し` `着手中` `未着手` のカードは、何件あっても退避しない。

## 統括への依頼（開発が書く・開発が 2 枚以上のとき）

開発が 2 枚以上あるとき、**開発はカード外の新しい作業を自分で起票しない**（2 枚が同時に次の番号を取って衝突する／統括の交通整理を迂回する）。代わりにここへ 1 行追記し、統括がカード化する。開発が 1 枚のときは従来どおり自分で起票してよい（`rules/modes/developer.md` §4）。

- `[ ] YYYY-MM-DD HH:mm / dev-B — <ユーザーの直接指示の要約>／触りたいファイル：<パス>`

統括は**起動時と、各カードの検品時にこの節を読み**、交通整理を通してから `H-NNN` を起票し、行を `[x] → H-NNN` にする。
