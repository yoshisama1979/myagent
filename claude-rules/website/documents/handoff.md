# 委任台帳（handoff）

**統括セッション（`/director`）と開発セッション（`/dev`）の受け渡しは、このファイルだけが正。**
2つのセッションは別のウィンドウで動き、**互いの会話は見えない**。ここに書かれていないことは、相手にとって存在しない。

> このファイルのパスは **固定**（`documents/handoff.md`）。`project-config.md` で変更できるようにはしていない
> ＝両セッションが別のファイルを見る事故を防ぐため。

---

## 状態と所有者（この6つだけを使う）

| 状態 | 誰が設定するか | 意味 |
|---|---|---|
| `未着手` | **統括** | 起票した。開発が着手できる |
| `着手中` | **開発** | 実装している |
| `質問中` | **開発** | 判断が要る。**統括の回答待ち** |
| `レビュー待ち` | **開発** | 実装が終わった。**統括の検品待ち** |
| `差戻し` | **統括** | 検品で条件未達。開発が直す |
| `クローズ` | **統括** | 検品を通り、コミットまで済んだ |

- **統括が拾うもの** ＝ `質問中` `レビュー待ち`
- **開発が拾うもの** ＝ `未着手` `着手中` `差戻し`
- 🚨 **今の状態を設定した側だけが、次の状態へ動かせる。** 相手の持ち場の状態を書き換えない

```
統括: 未着手 ──→ 開発: 着手中 ──→ 開発: レビュー待ち ──→ 統括: クローズ
                    │                      │
                    ├──→ 開発: 質問中       └──→ 統括: 差戻し ──→ 開発: 着手中
                    │        └──→ 統括が回答して 未着手 へ戻す
```

## 書き込むときの約束（両セッション共通）

1. **書く直前にこのファイルを読み直す**（相手が更新しているかもしれない）
2. **対象のカードだけを直す。** ファイル全体を書き戻さない
3. 読んだ状態が**想定と違っていたら、書かずに止まる**（相手が動いた＝前提が変わった）
4. `更新` 行を必ず自分の名前と日時にする

---

## カードのフォーマット

```markdown
### H-NNN <やることの見出し>

- 状態: 未着手
- 優先度: 1
- 依存: なし
- 更新: YYYY-MM-DD HH:mm / director

**やること**（1行）

**対象**（必須）
- 触るファイル

**受け入れ条件**（必須・完了を機械で判定できる形で）
- [ ] 条件1
- [ ] 条件2

**触らない範囲**（必須）
- スコープ外・壊してはいけないもの

**使う確定事実**（コンテンツを書くとき必須）
- `documents/company-facts.md` の該当箇所。ここに無い事実は書かせない（`【要確認】` を残して質問で返す）

**デザインの根拠**（見た目を触るとき必須）
- `Design.md` の該当トークン。新しい値が要るなら実装せず質問で返す

**読むルール**
- 例: `rules/modes/page-update.md`

**確認環境**
- `project-config.md`「URL・確認環境」
```

- **`- 状態:` `- 優先度:` `- 依存:` `- 更新:` の4行は固定形式**（行頭から書く）。見出しに状態を埋め込まない＝**grep で拾えるようにするため**
- `優先度` は 1 が最優先。`依存` は先に終わっている必要があるカード（`H-002` 等・無ければ `なし`）
- 開発は **`依存` が解決済みで、最も優先度の高いカード**から着手する（ユーザーに順番を聞かない）
- **1カード＝1論点。** 複数ページをまとめて1カードにしない（検品も差し戻しもできなくなる）
- 通し番号 `H-NNN` は連番で続ける

報告のフォーマットは `rules/modes/developer.md` §7 を参照。

## 退避（ローテーション）

次のどちらかに達したら、`クローズ` のカードを古い順に `documents/handoff-archive.md` へ移す（削除しない）。

- **`クローズ` が 50 件を超えた**
- **このファイルが 1000 行を超えた**

`質問中` `レビュー待ち` `差戻し` `着手中` `未着手` のカードは、何件あっても退避しない。
