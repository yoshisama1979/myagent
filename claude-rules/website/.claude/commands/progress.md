制作中の案件の進捗を確認し、**次の一手を提示**してください。

## 必読ファイル

1. `rules/modes/build-progress.md` — 制作進行モードの動作ルール（台帳の持ち方・記法・回し方・促し方・完了判定）

## 実行手順

1. 必読ファイルを読み込む
2. 台帳を読む（**会話の記憶から進捗を語らない**）
   - 単一案件：`documents/build-checklist.md`
   - 複数案件：同ファイル（ハブ＝案件一覧＋サイト共通の項目）＋ 対象案件の `documents/build-checklist/<案件ID>.md`
   - 無ければ、同 §1 に従って**用意を提案**する（配布物のひな形を案件用に展開・採番する。勝手に作らない）
3. 台帳と実状態のズレを確認し、ズレていれば先に台帳を直す（同 §6）
4. 次の一手を選ぶ（ブロッカー → ユーザー待ち → フェーズ順 → 効果×工数。同 §4 Step 2）
5. 「AI がやること」「ユーザーにお願いすること」「決めてほしいこと」を **合計3件まで**で提示する
6. 合意を得た項目だけ着手し、終わった項目は**その都度**台帳を更新する

## 重要

- **確認できたものだけ `[x]` にする**（実装した記憶・「送ると言われた」は完了ではない）
- **該当しない項目は削除せず `[-]`＋理由**で閉じる。見送り合意なら `PI-NNN` を併記する
- `[?]` を再掲したら `督促:` を +1 し、**2以上の項目は報告の冒頭に出す**。動いたら 0 に戻す
- **仮置きへの切り替え・見送りへの変更はユーザーの明示合意が要る**（AI の判断で待ちを畳まない）
- 追加してよいのは**合意済みの完成条件に必要な項目**まで。スコープを広げる改善は合意を取るか `documents/pending-issues.md` へ
- **フェーズ0〜6が片付いたら公開前ゲート**（`rules/modes/check.md` の A〜I）。台帳が全部埋まるのを待たない・ゲートを飛ばして「公開してよい」と報告しない
- **本番反映（デプロイ）は AI が実行しない**（`project-config.md`「デプロイ先・手順」）
