# project-config.md

> このプロジェクト固有の定義（サイト名・ディレクトリ構成・デプロイ先・公開URL・ブランチ運用・固有の値など）の置き場。各開発エージェントが記入する。
> **テンプレートをコピーしたら、まずここを記入する**。各ルールファイルは固有値を本文に持たず、このファイルを参照する。

## 基本（`CLAUDE.md` / 各ルールが参照）

- サイト名／クライアント名：（記入。例: 株式会社サンプル コーポレートサイト）
- プロジェクトルート：（記入。例: c:/xampp/htdocs/example）
- ディレクトリ構成の要点：（記入。例: HTML直下＋`css/sass/`＋`images/`、共通部品は `include/`）
- 確認・公開URL（ローカル／ステージング／本番）：→ 下記「**URL・確認環境**」節に記入
- デプロイ先・手順：（記入。例: FTPで本番へ手動アップ／開発者が実施。**AIはデプロイしない**＝`git push`・本番サーバーでのコマンド実行・FTPアップロードはすべてユーザーが行う）
- ブランチ運用：（記入。例: main 直コミット／feature ブランチ運用）

> ⚠️ **デプロイ手順を推測で書かない**：反映先・ブランチ・公開ディレクトリは**この欄の記入を正**とし、空欄なら**ユーザーに確認する**。
> ブランチ名から昇格経路を推測しない（使われなくなった古いブランチが残っていることは普通にある）。
> 反映状況を答える前に、**実状態を読む**（`git log -1 --oneline` / `git branch --show-current` / `git status --short`／公開URLを実際に GET する）。
> 「アップした」と「公開URLで確認できた」は別物として報告する（[rules/modes/hp-loop-dialogue.md](rules/modes/hp-loop-dialogue.md) §5-2 と同じ規律）。

## エージェント構成（`rules/modes/director.md` / `rules/modes/developer.md` が参照）

> **このプロジェクトを何枚のウィンドウで回すか。** 統括セッション（`/director`）が起動時の環境点検でここを読み、
> 開発セッションが開かれていなければ、**下の手順をそのまま貼って**ユーザーに開くよう伝える。

- **2セッション構成を使うか**：（記入。**`使う` または `使わない` のどちらかを書く**。既定は `使う`＝統括 `/director` と開発 `/dev` を別ウィンドウで開く。`使わない`＝1セッションで全部やる場合は、`director.md`／`developer.md` と各コマンドの役割分担・コミット制限がすべて無効になり、従来どおり `CLAUDE.md` のルール表に従う）
- **開発セッションの開き方**：（記入。**ユーザーがそのままなぞれる手順**で。例: ①新しいターミナルで `c:/xampp/htdocs/example` を開く ②`claude` を起動 ③`/dev` と打つ）
- **統括セッションの開き方**：（記入。例: 同上で `/director` と打つ。ふだん最初に開くのはこちら）
- **開発セッションの枚数**：（記入。既定は `1`＝`/dev` を引数なしで開く（名前は `dev-A`）。2 枚以上開くなら `/dev dev-A` `/dev dev-B` … と名前を付けて開き、統括がカードの `担当:` で割り当てる。**上限 3**〔`rules/modes/director.md` §5.1 の交通整理〕。枚数を増やすほど、ユーザーの中継（切り替えの声かけ）がその分増える）
- **委任の閾値の調整**：（記入。無ければ「既定どおり」。既定＝制作ファイルの変更はすべて開発へ渡し、統括が自分で触るのは `documents/` と、判断を伴わない数行の修正だけ〔`rules/modes/director.md` §4〕）

## URL・確認環境（`rules/modes/check.md` / `rules/modes/build-progress.md` / `rules/modes/page-update.md` / `rules/modes/refactor.md` が参照）

> **作ったものをどこで見られるかの記録。** 表示確認・スクリーンショットが要るとき、AI は毎回ユーザーに聞かず**まずここを見る**。
> 🚨 **`（記入。例: …）` が残っている行は「未記入」として扱う**（例の値をそのまま確認先に使わない）。未記入なら一度だけ確認し、**ここに記入してから**進む（次回以降は聞かない）。

| 環境 | URL | 備考 |
|---|---|---|
| ローカル | （記入。例: `http://localhost/example/`） | 実装中の確認先。ローカルサーバーが無くファイル直開き（`file://`）ならその旨を書く |
| ステージング・プレビュー | （記入。例: `https://stg.example.com/`） | Basic認証: あり／なし（🚨 ID・パスワードの実値は書かない） |
| 本番（公開URL） | （記入。例: `https://www.example.com/`） | 公開前は「未公開」と明記 |

- **既定の確認先**: （記入。例: 実装中＝ローカル／クライアント確認＝ステージング／反映後の実測＝本番）。**今回どれを見るか迷ったらこの欄に従う**（複数記入済みでも確認先が決まる）
- **空欄で放置しない。** 無いものは「無し」「未構築」「未公開」と書く（空欄だと「未記入」なのか「存在しない」のか判別できず、結局ユーザーに聞くことになる）
- **更新するタイミング**: ステージング開設時・本番公開時・URL変更時・ローカルの起動方法が変わったときに**その場で書き換える**。とくに「未構築」「未公開」と書いた行は、**環境ができた時点で必ず更新する**（書いた瞬間に空欄でなくなるため、更新しないと古い記述が残り続ける）
- **納品単位が複数ある案件**（LP が複数 等）は、**案件ごとに小表を分ける**（`### <案件ID>` の見出し＋同じ3列。1つの表に複数案件の行を混ぜない＝どの案件のURLか対応付かなくなる）。案件IDは `documents/build-checklist.md` の案件一覧と**完全一致**させる
- 🚨 **認証情報（Basic認証・管理画面・FTP・DB）の実値はここに書かない。** 「あり／なし」と保管場所までにとどめる（`documents/build-checklist.md` と同じ規律）。**URL 自体にも埋め込まない**（`https://user:pass@…` 形式・認証トークン付きクエリのURLは不可）
- **「デプロイ先・手順」との違い**: あちらは**反映の経路**（どこへ・どう上げるか）、この節は**ブラウザで見るアクセス先**。同じ情報を両方に書かない
- 「アップした」と「公開URLで確認できた」は別物（`rules/modes/check.md` J）。**確認したと書けるのは、実際にその URL を開いた／取得したときだけ**

## 見積もり（`rules/modes/estimate-format.md` が参照）

> クライアント向け見積もりの固有値。**空欄のまま金額を作らない**＝未記入なら一度だけユーザーに確認し、**ここに記入してから**進む（次回以降は聞かない）。
> 🚨 **`（記入。例: …）` が残っている行は「未記入」として扱う**（例の値をそのまま金額の根拠にしない）。無いものは「無し」と書く。

- **標準の人日単価**：（記入。例: 30,000円／人日・税別）＝定価を作るときの単価
- **採算下限の人日単価**：（記入。例: 20,000円／人日・税別）＝**これを下回ったら原価割れ**。標準単価とは別の値で、`rules/modes/estimate-format.md` §7 の判定に使う。🚨 **AI が決めない**（未記入なら一度ユーザーに確認して記入する。標準単価で代用すると、1%の割引でも赤字判定になり判定が壊れる）
- **標準の割引方針**：（記入。例: 10〜15%。⚠️ 過去案件の大幅割引は**ページ数が多く量に余裕があったから成立したもの**。**ページ数が少なくシステム比重が高い案件に同率を当てると原価割れする**＝`rules/modes/estimate-format.md` §7 の人日換算チェックを必ず通す）
- **見積書の宛先**：（記入。**元請け経由なら元請け社名**。エンドクライアント宛と混同しない）
- **請負範囲**：（記入。**範囲外も明記する**。例: コーディング・デザインのみ／ディレクション・IA・ワイヤーは元請け担当）
- **見積書の正本パス・命名規則**：（記入。例: `documents/estimate/<案件ID>_見積_v<版>.csv`）＝**どれが正のファイルか**の唯一の答え。書き込みが `EPERM` 等で失敗して別名保存したときは、**ここへ反映するまで作業を完了にしない**（`rules/modes/estimate-format.md` §4）
- **過去見積の置き場**：（記入。例: `documents/tmp/`。無ければ「無し」）
- **単価体系の参照先**：（記入。例: `documents/pricing-reference.md`。無ければ「無し」）
- **消費税**：（記入。例: 10%。見積書を**税別表記／税込表記**のどちらにするかも書く）

- 対になる分析ループのID（報告の宛先）：（記入。`hp-loop-<site>` 形式。例：hp-loop-ycom）
