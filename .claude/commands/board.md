# /board — 経営会議

**まず読む**：[rules/modes/board.md](../../rules/modes/board.md)（このモードの正）

## これは何のためにあるか

モード地図19本は全部が「日」か「案件」の単位で、**「月〜四半期 × 会社の方向」を持つ器が無かった**。
`partner` は「経営横断・能動・頂点」と定義されているのに、実際に出しているのは日次の督促である
（2026-09-06 の今日の一手＝「ある外注先へ1行送る（3分）」）。**毎朝という締切がある器は、
日次で完結する話しか出せない。**

だからこのモードは **決めるだけ**。実行は持たず、定時実行もしない。

## 起動時にやること（この順に）

0. `bash bin/office-beacon.sh start board "経営会議" "" cmd-board` — 机を点灯
1. **`python3 bin/board-brief.py`** — 決定台帳の現在地。
   **exit 1 なら見直し期日が来た決定がある＝会議の冒頭で必ず扱う**
2. `site/business/goals.html` — 北極星（目標ツリー）の現在地
3. `data/partner/ledger.md` の **§1・§2 だけ**（全文は読まない＝18万字超）
4. `財務スナップ取得:` が **6日以上前なら** `python3 bin/finance-snapshot.py`
5. 月初・四半期（4/7/10/1月）のときだけ `data/partner/milestones.md`

## 会議で立てる問いは4つだけ

1. **現在地はどこか**（数字で。推測で埋めない）
2. **目標はまだ正しいか**（← board にしかできない仕事）
3. **社長の時間・金・人をどこへ配るか**（**やめる決定**を出せる場にする）
4. **次に見直すのはいつか**

社長へ出すときは **A案／B案＋AI の推薦と根拠**。「どうしますか」は禁止。

## 決まったら

1. `data/board/decisions.md` の「決定一覧」に **1行追記**（7列固定・`見直し` と `降ろし先` は必須）
2. **降ろす**：
   - 社長が動く → ToDo 起票案（**登録は社長合意後・マネジメントか `/intake` が実行**）
   - AI にやらせる → **社長が別ウィンドウで `claude` を立て「board の D-00N を読んで」**
   - 毎日の伴走に落とす → **`goals.html` を更新**（社長承認後）＝翌朝から partner がそれを見る

## やってはいけないこと

- **実行を始める**（会議が作業に化けると、決める時間が消える）
- **日次に降りる**（「今日の一手」は partner の領分）
- **見直し期日の無い決定・降ろし先の無い決定を書く**
- **台帳の行を消す・書き換える**（取りやめは `dropped`／置き換えは `superseded:D-NNN`）
- **他モードの台帳・hana-tools を直接書き換える**
- **cron に載せる**（定時実行しないのが設計）

## セッションを終えるとき

`bash bin/office-beacon.sh stop board cmd-board`
