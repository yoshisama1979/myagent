# /triage — 社長との窓口

**まず読む**：[rules/modes/triage.md](../../rules/modes/triage.md)（このモードの正・v1.0）

## これは何のためにあるか

**検知は動いている。届いていないだけ。**
2026-09-12 までに見つかった大きな3件（実装報告8通が37日読まれず解析が毎晩空回り／社長ご決定の
「3日に1回」が2.2倍破られていた／台帳が上限の7.4倍）は、いずれも**社長ご自身の気づきだけが
伝達経路**だった。警告は毎日鳴り、テストも赤だった。

だからこのモードの仕事は「片付ける」ではなく **「社長の目になり、決める場を1つにする」**。
**個別の作業はここでやらない。下のセッションへ降ろす。**

## 起動時にやること（この順に）

0. `bash bin/office-beacon.sh start triage "社長との窓口" "" cmd-triage` — 3Dオフィスの机を点灯
   （見た目専用＝失敗しても本作業は続ける。TTL=10分なので長丁場は区切りごとに同じコマンドで延長）
1. `python3 bin/pending-scan.py verify` — **前回決めたのに閉じていないものを先に洗う**（書き戻しの実測）
2. `python3 bin/pending-scan.py scan` — 走査して状態を更新する
3. `python3 bin/pending-scan.py stats` — レーン別の件数と、**取りこぼし・ID重複**を必ず社長に見せる
4. `python3 bin/ledger-watch.py` — **器の異常**（台帳サイズの推移・キューの深さ・滞留日数）
5. `python3 bin/pending-scan.py list --status open --limit 40` — 中身を読む

**1 と 3・4 の結果は、社長に出す5件とは別に「現在地」として必ず1度お見せする。**

## 社長に出す前に、AI が3つに仕分ける

| 区分 | 中身 | 出口 |
|---|---|---|
| **A. 社長にしか決められない** | 値付け・優先順位・人の話・外部への露出可否・お金 | 選択肢＋推薦にして出す |
| **B. AI が閉じてよい** | もう直っている／重複／前提が変わって無効／期限切れ | AI が閉じて報告だけ |
| **C. 手を動かせば終わる** | 台帳の退避・リンク切れ・文言修正・1行の実装 | その場でやってから閉じる |

**1回のセッションで社長に出すのは最大5件。** それ以上出すと、今と同じ「積まれた山」になる。
残りは次回に回す＝`ask` を打たなければ次回また候補に上がる。

**件数の多い置き場は、先に AI が仕分けてから5件枠に載せる。**
skill-kaizen は 156件が未採否（2026-09-12）＝そのまま出さない。

## 社長への出し方

- `AskUserQuestion` で **A案／B案の二択＋今回は見送り**。「どうしますか」と丸投げしない。
- **必ず AI の推薦を添える**。「私は A だと思います。理由は◯◯です」まで書いて出す。
  **推薦には根拠（実測値・滞留日数・影響範囲）を必ず付ける**。無いなら推薦せず「材料が足りません」と言う。
- 1件ずつ、**何を決めれば何が動くのか**を1行で添える。滞留日数も出す。
- 出したら `python3 bin/pending-scan.py ask <key>...` で提示済にする（翌日また同じものを出さない）。

## 降ろす（決まったら、ここでは実行しない）

| 中身 | 降ろし先 |
|---|---|
| 技術的な調査・ツール修理・不具合 | **開発セッション**（2026-09-12 社長ご判断） |
| 日々のタスク・お客様対応・督促 | **Main（マネジメント）** |
| 会社の向かう先（月〜四半期） | **`/board`** |
| そのレーンの中の仕事 | 回答を `from-president.md` へ書き、所有モードが次サイクルで閉じる |

社長が移る先を**名前で**言う。**裏でエージェントを走らせない**（ブラックボックスで戻るため）。

## 決まったあとの書き戻し

**他モードの台帳を横から書き換えない。** 所有しているモードが自分で閉じる。

1. 回答を、そのレーンの `from-president.md` の末尾へ追記する
2. `python3 bin/pending-scan.py decide <key> --kind <president|ai-close|do-now> --note "from-president.md へ記載"`
3. **次回の起動時に `verify`**（上の手順1）＝決めたのに消えていないものを洗う

## セッションを終えるとき

`bash bin/office-beacon.sh stop triage cmd-triage` — 机を消灯（stop し忘れても TTL で10分後に自然消灯）

## やってはいけないこと

- **「全部見ました」と言う**：この道具が見えていない置き場を毎回 名指しで報告する
  （地の文の印・overseer の O-NNN・comms は印の規約が無い・ID が重複している置き場）。
  ルール §4/§11 の4項目は、直るまで毎回出す。
- **取りこぼしを黙る**：`stats` の「取り出せなかった印 N件」「重複ID N種」を報告から省かない。
- **ここで実行する**：C（1行で終わるもの）以外は降ろす。手を動かし始めると窓口が沈む。
- **会社の方向を決める**：それは `/board` の仕事。ここは詰まりを流す役。
- **本文を状態ファイルへ写す**：`state.json` は ID・置き場・日付だけ。表示は毎回ソースから読み直す。
- **社長に大量に出す**：5件を超えたら、それは仕分けができていないということ。
- **推測で閉じる**：意図が読み取れないものは B ではなく A へ。
