# Intake（取り込み）モード — 動作ルール

> **北極星：打ち合わせで決まったことが、その日のうちに「誰かが手を動かせる形」で HANAツールに入っていること。**
> 測るのは「登録した件数」ではなく、**後から誰かがそれを見て着手できたか**。

> **version 0.2**（2026-08-19・Codexレビュー反映）
> 発端＝2026-08-18 の UV 様打ち合わせで **8件中6件が登録できなかった**／柏病院2件は**期日の言及がなく仮置き**になった／
> 未完了 ToDo 78件のうち**担当者が全件未設定**だった。いずれも「入れる側」に型が無かったことが原因。
> **⚠️ 2026-08-21 更新**：担当欄そのものは**当面使わない**と社長がご決定（「Todo起票はとりあえずは私社長だけで進めましょう」）。
> **＝担当は社長固定・`assignee_user_id` は送らない・社長に担当を聞かない。** 誰がやるかは会話台帳の `担当:`（comms v0.9）で把握する。
> 土台＝進行管理の一次情報は hana-tools（2026-06-12 社長確定）。CLAUDE.md「メモ・議事録まとめのルール」。

**対話型。無人では動かさない。** 社長が走り書きを渡した場に呼ばれて動く。

## 手順（1回分）

### Step 0 — 原文をそのまま確保する
走り書きの**原文を一字も変えずに控える**。あとで description に丸ごと入れる。
清書した文だけを残すと、**社長の言い回しに含まれていた含みが消える**（例：「〜っぽい」「〜かも」＝未確定の合図）。

### Step 1 — 4つに分解する
| 種別 | 行き先 |
|---|---|
| **決まったこと**（やる・いつまでに・誰が） | hana-tools の ToDo |
| **まだ確定していないこと**（数字に「？」が付く、伝聞、感触） | ToDo にせず、**Step 6 と同じ記録ページの「要確認」節**に置く。確定値として扱わない・見積りの根拠にしない |
| **相手に約束したこと** | ToDo（**期日は動かせない**印を付ける） |
| **背景・経緯・議事録の本文** | `site/clients/<client>/projects/<project>/` |

### Step 2 — 登録先の案件を特定する
`bash bin/hana-api.sh projects` / `search <名前>` で探す。
- **見つかったら** work_id を控える
- **見つからなければ勝手に近い案件へぶら下げない**。案件が無い旨を社長に伝え、作成を依頼する
  （※ 案件作成 API は未実装＝A-066。実装されるまでは社長が画面から作る）
- 見つかった案件が `status: completed` なら、**そこにぶら下げてよいか確認する**

### Step 3 — 足りない項目を「1回で」聞く
下の6項目のうち**埋まっていないものだけ**を、**選択肢形式でまとめて1度に**聞く。
何度も往復すると、走り書きを渡すほうが面倒になり、この仕組みは使われなくなる。

### Step 4 — 登録案を提示する
**書き込む前に必ず**、表で示す：`内容／案件／期日／出典`（**担当は社長固定＝聞かない・出さない**＝2026-08-21 社長ご決定）。

**⚠️ AI が考えた値を「仮置き」として入れてはいけない**（2026-08-19 Codexレビュー🔴）。
「仮置きと書けば推測してよい」は抜け道になる。**社長が表全体に「OK」と返した瞬間、AI の推測が本登録される。**
- 期日が分からない → **登録しない**。「Step 6 の未登録」へ回して、決まってから入れる
- 仮の値を入れてよいのは、**社長が「仮でいいから入れて」と指定したときだけ**（誰の仮値かを description に書く）

### Step 5 — 合意を得てから登録する

**合意は状態で管理する：`下書き → 承認待ち（Step 4 で提示） → 明示承認 → 実行`。**
- **「了解」「続けて」「よろしく」では書かない。** 実行してよいのは「**この N 件を登録して**」のように
  **対象が特定できる返事**だけ（2026-08-19 Codexレビュー🔴）
- **提示後に内容が1つでも変わったら、承認は無効**。作り直して提示しなおす
- 承認の範囲は**提示した表の中だけ**。ついでの追加登録・共有メモへの転記は**別に承認を取る**

- ToDo：`bash bin/hana-api.sh create-todo '<JSON>'`
- 議事録・経緯：`site/clients/.../`（`rules/memo.md` の構成に従う）
- 案件の共有メモ：`bash bin/hana-api.sh update-note <project_id> '<JSON>'`
  → **shared は全員が見る**。値付けの考え方・人間関係の機微・交渉方針は入れない（それらは partner 台帳へ）

### Step 5.5 — 途中で失敗したら、最初からやり直さない
複数件を順に登録する途中で API エラーが出ることがある。**そのまま再実行すると、成功済みの分が二重登録される**
（2026-08-19 Codexレビュー🔴）。
- 登録した順に **成功した id を控える**（報告にも出す）
- 再実行する前に `bash bin/hana-api.sh todos --work_id=<id>` で**既に入っているものを確認**する
- **失敗した1件だけ**を入れ直す。全件を投げ直さない

### Step 6 — 登録できなかったものを残す
案件が無い等で入らなかった分は、**そのまま消さず**に `site/drafts/` の記録ページと partner 台帳に残し、
**「何が揃えば登録できるか」**を1行で書く。

## 必ず埋める6項目

走り書きに書かれていないことが多い。**書かれていなければ聞く。推測で埋めない。**

| # | 項目 | なぜ（実際に詰まった例） |
|---|---|---|
| 1 | **どの案件か** | 2026-08-18 UV 様の8件中6件が、案件が無くて登録できなかった |
| 2 | **担当は誰か** | 未完了78件すべてで `assignee_user_id` が未設定＝画面から誰のボールか読めない。**⚠️ 2026-08-21 社長ご決定＝<u>ToDo の起票は当面すべて社長（`assignee_user_id` は入れない）</u>**（原文＝「Todo起票はとりあえずは私社長だけで進めましょう」）。会話台帳の `担当:`（comms v0.9）は**把握用であって ToDo の担当欄には反映しない**。運用を変えるのは社長のご指示があったときだけ |
| 3 | **期日。自社の期日か、先方の期日か** | 柏病院2件は期日の言及がなく仮置きになった |
| 4 | **決まったことか、まだ確定していないか** | 「60Pくらい？」「フォーム3つ？」を確定値と誤読しかけた |
| 5 | **相手に約束したことか** | C-060 は社長ご自身が「来週水曜まで」と明示＝重みが違う |
| 6 | **出典（いつ・誰との話か）** | 後から遡れないと、指示の実体（添付・原文）に辿り着けない |

## 厳守する制約

1. **推測で埋めない。** 埋めたら必ず「仮置き」と書く（CLAUDE.md「メモ・議事録まとめのルール」）
2. **書き込み前に登録案を提示する。** hana-tools は共有システム＝勝手に書かない（rules/automation.md §3）
3. **原文を description に丸ごと残す。** 清書だけにしない
4. **同じものを2か所に書かない。** 進行＝hana-tools／背景＝`site/`（2026-06-12 社長確定）。
   **ただし「原文」だけは例外＝1か所にだけ全文を置き、他からは参照する**（2026-08-19 Codexレビュー🔴）：
   - 走り書きの**全文を置くのは1か所**（議事録を作るならそこ／作らないなら代表 ToDo 1件の description）
   - 他の ToDo には**その件に関わる部分と、全文の在りか**だけを書く
   - 未登録分・未確定分の置き場も**1か所に決める**（既定＝`site/drafts/` の記録ページ。partner 台帳には
     「実害と判断」だけを A-NNN で1行。**内容を丸写ししない**）
5. **完了マークは付けない。** 「終わった」と判断できるのは社長・担当者だけ。社長が明示したときだけ閉じる
6. **クライアント機密・秘密情報を共有メモに書かない**
7. **日付は JST で扱う。** hana-tools の `due_date` は JST 0時を UTC（`T15:00:00Z`）で保存する＝
   日付部分をそのまま読むと**1日早くずれる**（2026-08-18 に実際に間違えた）

## やってはいけないこと

- 案件が見つからないからといって、**近い案件に仮でぶら下げる**（後から誰も気づけない）
- 期日が書かれていないからといって、**期日なしで登録する**（期日なしは「いつまでも今日ではない」）
- 走り書きの曖昧な数字を、**見積りの根拠に使う**
- 一度に何度も質問を往復する（**1回にまとめる**）

## 自己チェック（登録の前に）

- [ ] 原文をそのまま残したか
- [ ] 6項目のうち、埋まっていないものを聞いたか
- [ ] 推測で埋めた箇所に「仮置き」と書いたか
- [ ] 登録案を社長に提示して合意を得たか
- [ ] 未確定の数字を、確定値として書いていないか
- [ ] 同じ内容を hana-tools と `site/` の両方に書いていないか
- [ ] 共有メモに、値付け・人間関係・交渉方針を書いていないか
